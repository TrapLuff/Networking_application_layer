# Создание структуры документа

## LLM вариант 6

Создание структуры документа. Пользователь вводит тему документа, агент генерирует структуру (оглавление, разделы, подразделы) и возвращает частями.

## Прикладной уровень

Веб-интерфейс реализован на React, Redux Toolkit, Axios и MUI. В нём есть поле для текстовой темы и карточки с нумерованными разделами и подразделами. Ориентиром для дизайна послужил [Storyflow AI Outline Generator](https://storyflow.so/ai-outline-generator).

После входа по логину браузер открывает поток Server-Sent Events (SSE) через `GET /api/events`. Сервер Express отправляет по этому потоку результаты в сессию пользователя, который запустил генерацию. Кнопка **Выйти** завершает сессию, закрывает поток и очищает рабочую область. При обновлении страницы тема и карточки очищаются, а вход сохраняется.

Прикладной сервер обменивается с транспортом JSON по HTTP.

| Метод | Маршрут | Данные |
| --- | --- | --- |
| `Send` | `POST /api/v1/send` | Прикладной сервер отправляет логин пользователя (`sender`), время запроса в миллисекундах Unix (`timestamp`) и текст темы (`document_topic`). |
| `Receive` | `POST /api/receive` | Транспорт возвращает исходные `sender` и `timestamp`, признак ошибки `error` и текст структуры в `payload`. При передаче по частям используются `part_number` и `total_parts`. При ошибке `payload` равен `null`. |

Когда транспорт присылает результат частями, карточки появляются по мере поступления. Если приходит ошибка, интерфейс показывает карточку «Ошибка получения данных» со значком ошибки и сохраняет уже полученные разделы.

Примеры JSON и событий SSE приведены в [спецификации API](openapi.yaml).

## Локальный запуск

Для локальной демонстрации заглушка транспорта возвращает шаблонный план из шести разделов. Для генерации через отдельный агент можно подключить транспортный сервис.

Понадобятся Node.js 24 с npm и современный браузер, например Chrome, Firefox или Яндекс Браузер.

1. Скачайте или клонируйте репозиторий и откройте папку с `package.json`.
2. Установите зависимости и создайте `.env` из `.env.example`. Если `.env` уже настроен, пропустите копирование и проверьте его параметры по шаблону.

   **Windows (PowerShell)**

   ```powershell
   npm.cmd ci
   Copy-Item .env.example .env
   ```

   **macOS и Linux**

   ```bash
   npm ci
   cp .env.example .env
   ```

3. В этой же папке откройте три терминала и запустите по одной команде в каждом. В Windows используйте `npm.cmd` вместо `npm`.

   | Команда | Что запускает | Порт по умолчанию |
   | --- | --- | --- |
   | `npm run server` | Прикладной сервер Express | `3000` |
   | `npm run mock` | Локальную заглушку транспорта | `4000` |
   | `npm run dev` | Веб-интерфейс Vite | `5173` |

4. Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Оставьте процессы запущенными на время работы. Для остановки нажмите `Ctrl+C` в каждом терминале.

## Руководство пользователя

### Вход

В поле **Логин** введите один из тестовых логинов и нажмите **Войти**. Для демонстрационного входа достаточно логина. После входа имя появится в правом верхнем углу.

| Логин из `.env.example` | Имя в интерфейсе |
| --- | --- |
| `loudjik` | Лоуджик |
| `sasha` | Саша |

### Создание структуры

1. В поле **Введите тему документа** укажите тему длиной до 300 символов, например «Применение солнечной энергии в жилых домах».
2. Нажмите **Сгенерировать**. До получения результата появится сообщение «Генерируем структуру…».
3. Просмотрите карточки разделов и списки подразделов внутри них. Во время загрузки по частям рядом с именем пользователя отображается счётчик.
4. После завершения запроса можно изменить тему и запустить генерацию снова. Новый запрос заменяет предыдущий результат на экране.

### Ошибки и выход

- Если появилось сообщение «Неизвестный логин», проверьте написание и сверьте логин с настройками в `.env`.
- Если транспорт недоступен, проверьте, что запущен `npm run mock` или подключённый транспортный сервис, и отправьте тему повторно.
- Если появилась карточка «Ошибка получения данных», прочитайте причину под заголовком. Когда кнопка **Сгенерировать** снова доступна, можно повторить запрос. Чтобы проверить этот сценарий с локальной заглушкой, введите тему `Потеря сегментов`. Приложение покажет два раздела и затем сообщит об ошибке.
- Чтобы сменить пользователя, нажмите **Выйти** и войдите под другим логином.

## Подключение транспорта и агента через ZeroTier

Этот режим требует запущенных транспортного сервиса и агента. Устройства должны быть в одной сети ZeroTier.

1. В `.env` прикладного уровня задайте `APP_RECEIVE_HOST` с ZeroTier IPv4 компьютера, на котором работает Express, и `TRANSPORT_BASE_URL` с HTTP-адресом и портом транспортного сервиса. Для работы с агентом можно увеличить `GENERATION_TIMEOUT_MS` до `180000` (180 секунд).
2. На транспортном сервисе задайте `AGENT_URL` с полным адресом маршрута генерации агента и `APP_URL` со значением `http://<IP_ПРИКЛАДНОГО_КОМПЬЮТЕРА>:3000/api/receive`. Используйте значение `APP_PORT`, если порт Express менялся.
3. Запустите `npm run server` и `npm run dev`, затем откройте тот же адрес веб-интерфейса.

## Логирование ответов транспорта

Чтобы включить логирование, задайте параметр в `.env`.

```dotenv
LOG_TRANSPORT_RESPONSES=1
```

Перезапустите прикладной сервер командой `npm run server` (в Windows `npm.cmd run server`). В его терминале будут появляться записи о вызовах `POST /api/receive` с кодом HTTP-ответа и полученным JSON. Записи появятся и при работе с локальной заглушкой, и при подключении внешнего транспорта.

Чтобы отключить логирование, задайте `LOG_TRANSPORT_RESPONSES=0` и снова перезапустите сервер.
